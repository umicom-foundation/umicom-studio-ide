1. Batch outcome

Batch 58 establishes a toolkit-neutral compiler platform in Umicom Framework and a professional Compiler Centre in Umicom Studio. Studio does not implement compiler rules privately: it projects Framework providers, profiles, target triples, requests, plans, diagnostics, build graphs, ABI contracts, compilation databases, lockfiles, sysroots, runtimes and caches.

3. Professional Studio experience

The enclosed “Umicom Studio Ideas 2” document asks for Visual Studio familiarity, Beyond Compare-style comparison, comprehensive compile/build/deploy/package workflows, TWS-style subwindows and layouts, saved workspaces, grouped tabs, layout locking and modern themes. Batch 57 supplied the reusable workspace and operations foundations; Batch 58 supplies the compiler vertical slice that occupies those layouts.

Compiler perspective

A ready-made layout with Resource Explorer and compiler providers on the left, editors and build graph in the centre, properties/interoperability on the right, and Problems/Output/Terminal below.

Layout edit lock

Unlock to add, close, move, dock, split, resize or tab views; lock when finished so normal clicks cannot accidentally damage the workspace.

Context-linked groups

Colour-labelled window groups can follow the active project, target or compilation unit, inspired by TWS colour-linked Mosaic tools.

Layout library

Create a blank workspace, add views from a searchable catalogue, or start from Compiler, Debug, Polyglot, Operations and Trading presets.

Local persistence and recovery

Save named layouts locally, export/import them, retain revision history and restore a known-good layout after accidental changes.

Theme and density

Light, dark and high-contrast palettes, global font scaling, comfortable/compact density and view-specific configuration.

TWS inspiration was cross-checked against the official Mosaic Layout, Mosaic Anchor Window, Custom Layouts and Predefined Layouts guides. Umicom adopts general interaction ideas; it does not copy proprietary source or branding.

4. Windows prerequisites

Use one ABI family. These steps use MSYS2 UCRT64 throughout. Do not mix UCRT64 libraries with MINGW64, standalone LLVM or Visual Studio libraries in the same build directory.

  1. Install Git, CMake and MSYS2

    Install Git for Windows and MSYS2. The commands below assume MSYS2 is installed at C:\msys64. Start MSYS2 UCRT64 from the Start menu and update it:

    pacman -Syu --noconfirm
# Close and reopen MSYS2 UCRT64 if the terminal asks, then run:
pacman -Syu --noconfirm

  2. Install the native build and GTK packages

    pacman -S --needed --noconfirm \
  mingw-w64-ucrt-x86_64-toolchain \
  mingw-w64-ucrt-x86_64-clang \
  mingw-w64-ucrt-x86_64-cmake \
  mingw-w64-ucrt-x86_64-ninja \
  mingw-w64-ucrt-x86_64-pkgconf \
  mingw-w64-ucrt-x86_64-gtk4 \
  mingw-w64-ucrt-x86_64-gtksourceview5 \
  mingw-w64-ucrt-x86_64-json-glib \
  mingw-w64-ucrt-x86_64-libsoup

  3. Optional polyglot tools

    Install Rust with rustup and add Zig to a dedicated directory such as C:\Tools\zig. UAI/Umicc can remain unconfigured until its executable is available; Studio reports it as an optional provider rather than failing the whole toolchain.

  4. Verify from PowerShell

    $env:Path = "C:\msys64\ucrt64\bin;C:\Tools\zig;$env:USERPROFILE\.cargo\bin;$env:Path"
where.exe git
where.exe cmake
where.exe ninja
where.exe gcc
where.exe clang
where.exe pkg-config
gcc --version
clang --version
rustc --version
zig version
pkg-config --modversion gtk4

    If an optional command is not installed, its where.exe line may fail; continue if you do not need that language yet.

5. Extract and apply the batch

The download contains two overlays: Framework and Studio. Apply and publish Framework first. Only then update Studio’s Framework submodule, apply the Studio overlay and regenerate the version lock.

  1. Set your paths

    $BatchZip = "$env:USERPROFILE\Downloads\Umicom_Batch_58_Compiler_Polyglot_Umicc.zip"
$BatchRoot = "C:\Dev\umicom\batch58"
$FrameworkRoot = "C:\Dev\umicom\umicom-framework"
$StudioRoot = "C:\Dev\umicom\umicom-studio"
New-Item -ItemType Directory -Force -Path $BatchRoot | Out-Null
Expand-Archive -LiteralPath $BatchZip -DestinationPath $BatchRoot -Force

  2. Confirm clean repositories

    git -C $FrameworkRoot status --short
git -C $StudioRoot status --short

    Stop if either command lists work you have not intentionally saved. Commit or back up your own work before continuing.

  3. Apply the Framework overlay

    Copy-Item -Path "$BatchRoot\Framework\*" -Destination $FrameworkRoot -Recurse -Force
git -C $FrameworkRoot status --short

6. Build and test

6.1 Framework - headless compiler platform

Set-Location $FrameworkRoot
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
$env:CC = "C:\msys64\ucrt64\bin\gcc.exe"

cmake -S . -B build\batch58-ucrt64 -G Ninja `
  -DCMAKE_BUILD_TYPE=RelWithDebInfo `
  -DCMAKE_C_COMPILER="$env:CC" `
  -DUMICOM_ENABLE_STRICT_WARNINGS=ON `
  -DUMICOM_BUILD_GTK4_ADAPTER=OFF `
  -DCMAKE_INSTALL_PREFIX="C:\Dev\umicom\sdk\framework"

cmake --build build\batch58-ucrt64 --parallel
ctest --test-dir build\batch58-ucrt64 --output-on-failure
cmake --install build\batch58-ucrt64
Framework acceptance requires the new framework.compiler.* tests to pass, including provider registry, request planning, diagnostics, ABI graph, lockfile, cache and centre scenarios.

6.2 Publish Framework before building Studio

Use the exact first commit in section 12, push it, and then update Studio’s embedded Framework:

Set-Location $StudioRoot
git -C .\framework fetch origin main
git -C .\framework checkout origin/main
git -C .\framework rev-parse HEAD

6.3 Apply and build Studio

Copy-Item -Path "$BatchRoot\Studio\*" -Destination $StudioRoot -Recurse -Force
Set-Location $StudioRoot
. .\scripts\enter-umicom-ucrt64.ps1

cmake -S . -B build\batch58-ucrt64-debug -G Ninja `
  -DCMAKE_BUILD_TYPE=Debug `
  -DUMICOM_STUDIO_BUILD_GTK=ON `
  -DUMICOM_ENABLE_STRICT_WARNINGS=ON `
  -DCMAKE_INSTALL_PREFIX="C:\Dev\umicom\install\studio"

cmake --build build\batch58-ucrt64-debug --parallel
ctest --test-dir build\batch58-ucrt64-debug --output-on-failure

For a faster headless verification, repeat with -DUMICOM_STUDIO_BUILD_GTK=OFF in a different build directory.

7. Deploy and install

  1. Install to a versioned prefix

    Set-Location $StudioRoot
cmake --install build\batch58-ucrt64-debug `
  --prefix "C:\Dev\umicom\install\studio-b58"

  2. Make GTK runtime DLLs available

    For a developer installation, keep C:\msys64\ucrt64\bin at the front of PATH when launching. A future distribution batch will create a self-contained installer and copy only the audited runtime closure.

    $env:Path = "C:\msys64\ucrt64\bin;$env:Path"
& "C:\Dev\umicom\install\studio-b58\bin\umicom-studio-doctor.exe"
& "C:\Dev\umicom\install\studio-b58\bin\umicom-studio-compiler-centre-v2.exe"

  3. Launch the installed desktop application

    & "C:\Dev\umicom\install\studio-b58\bin\umicom-studio-ide.exe" --console

  4. Optional developer uninstall

    This repository does not yet provide a production uninstaller. To remove this developer installation, close Studio and remove only the explicit versioned prefix you created:

    $InstallToRemove = "C:\Dev\umicom\install\studio-b58"
if ((Test-Path $InstallToRemove) -and ($InstallToRemove -like "C:\Dev\umicom\install\studio-*")) {
  Remove-Item -LiteralPath $InstallToRemove -Recurse -Force
}

8. Use Umicom Studio

8.1 Create or open a project

  1. Launch Studio and select File → New Project or File → Open Workspace.
  2. Choose a starter: C23, C++23, C + Assembly, Rust, Zig, UAI or Polyglot Console.
  3. When Studio asks for workspace trust, inspect the project and grant trust before allowing compiler execution.

8.2 Configure compilers

  1. Open View → Compiler Centre, or use the Command Palette and run Compiler: Detect Compilers.
  2. Review provider availability, executable, family, languages and target triple.
  3. Select a profile such as Host Debug. The first detected C-capable provider becomes the initial profile; change it explicitly if you prefer Clang or Umicc.
  4. For Rust, Zig or UAI units, select their provider in the unit manifest or allow language-based resolution.

8.3 Build and diagnose

  1. Press Ctrl + Shift + B or run Compiler: Build Active Project.
  2. Open Build Graph to inspect ordered compile, assemble and link steps.
  3. Open Interop Boundaries to confirm that every cross-language edge uses a compatible ABI profile.
  4. Use Compiler Problems for normalised diagnostics and Compiler Output for raw provider output.
  5. Export compile_commands.json for editor tooling and refresh the compiler lockfile after intentional provider or target changes.

8.4 Arrange and save your layout

  1. Click the layout padlock to enter Unlocked/Edit mode.
  2. Use New Window to add Compiler Providers, Build Graph, Interop Boundaries, Problems, Output or Terminal.
  3. Drag a title bar to dock left, right, top, bottom or centre-as-tab. Drag splitters to resize. Assign a colour group when views should follow the same active project or unit.
  4. Click + in the workspace tab strip to create another named layout, or open the Layout Library for a preset.
  5. Select light/dark theme, density and font scale. Lock the layout when finished, then use Save Layout As.

8.5 Native command examples

# Inspect configured compiler providers
& .\build\batch58-ucrt64-debug\bin\umicom-studio-compiler-centre-v2.exe `
  "C:\msys64\ucrt64\bin\gcc.exe" `
  "C:\msys64\ucrt64\bin\clang.exe"

# Generate and print a polyglot compilation database example
& .\build\batch58-ucrt64-debug\bin\umicom-studio-polyglot-compiler.exe

9. Troubleshooting

SymptomCauseResolution
gtk/gtk.h not foundGTK4 package or UCRT64 pkg-config path is missing.Re-run the UCRT64 package command, put C:\msys64\ucrt64\bin first on PATH, then verify pkg-config --cflags gtk4.
DLL not found at launchThe developer install does not yet bundle GTK runtime DLLs.Launch from the prepared PowerShell environment or prepend the UCRT64 bin directory to PATH.
CMake selected the wrong compilerAn old build directory cached standalone LLVM or MSVC.Use a new build directory and pass the absolute UCRT64 compiler path.
Compiler provider is “missing”The executable path is empty or unavailable.Open Compiler Centre settings, select the executable and re-run detection.
ABI boundary is incompatibleProducer and consumer disagree on target, pointer width, object format or ABI kind.Align target triples and use an exported extern "C"/extern "C"-equivalent boundary.
Framework header not found in StudioStudio’s Framework submodule is still on the pre-B58 commit.Fetch and check out the Framework commit you published before configuring Studio.
Layout panels move accidentallyThe workspace remains unlocked.Save the layout and click the padlock to return to Locked mode.
VERSION_LOCK.json has old versionsThe lock was not regenerated after updating the submodule.Run .\scripts\update-version-lock.ps1 immediately before the Studio commit.

10. Acceptance checklist

  • Framework configures and builds with strict warnings enabled.
  • All Framework tests pass, including every framework.compiler.* test.
  • Framework installs headers, templates, Umicom::compiler and the aggregate Umicom::Framework export.
  • Studio’s Framework submodule points to the published Batch 58 Framework commit.
  • Studio builds both headless tools and the GTK desktop application.
  • All studio.compiler_* and studio.umicc_polyglot_v2 tests pass.
  • Compiler Centre lists GCC/Clang plus any installed Rust, Zig and Umicc tools.
  • A template project can be opened, planned and represented in the compilation database.
  • The installed doctor, Compiler Centre tool and IDE launch from the installation prefix.
  • A custom Compiler layout can be unlocked, rearranged, saved and locked.
  • VERSION_LOCK.json records the new Framework commit and current CMake versions.

11. Exact Git sequence

Required order: Framework commit and push first. Then update Studio’s Framework submodule, regenerate VERSION_LOCK.json, and commit/push Studio.

Commit 1 - Umicom Framework

Set-Location $FrameworkRoot
git status --short

Set-Location $StudioRoot
